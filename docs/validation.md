# Тесты и валидация

Три уровня. Все запускаются в контейнере, критерии заданы заранее (`config/validation/criteria.yaml`).

| Уровень | Команда | Время (8 ядер) | Что проверяет |
|---|---|---|---|
| Модульные тесты C++ | `./run.sh test` (часть) | секунды | классификация историй (разложение полное, фотопоглощение ≠ рассеяние), сетка и сумма квадратов по историям, колонки, таблица источника |
| pytest | `./run.sh test` | ~30 с | спектр (E_c, G₁, нормировка мощности, интеграл Швингера), NIST и правило смеси, геометрия всех конфигураций, нормировка (сверка с диссертацией), анализ, формулы из DOCX, модель проявления, 13 синтетических тестов интерферометрии, инвентаризация архива, баланс энергии в коротком прогоне Geant4 |
| Физическая валидация | `./run.sh validate --quick` (~5 мин), `./run.sh validate` (~1 ч) | | ТЗ п. 4.4, 5.3, 7.3, 8.3, 11 — ниже |

## Исправления критериев после первого прогона

Зафиксированы в отчёте (раздел «Исправления критериев»): (1) GPS — критерий «≤5 % в каждом бине»
статистически некорректен → χ²; (2) μ/ρ vs NIST — добавлена статистическая погрешность μ_MC;
(3) доли взаимодействий — 3.5σ на каждое из 111 сравнений → биномиальный тест с поправкой Бонферрони
(первый прогон дал 3.68σ для Ti 5 кэВ); (4) сходимость статистики — сравнение σ одиночных прогонов
неустойчиво при тяжёлом хвосте весов → ансамбль независимых зёрен. Кроме того, после первого прогона
в принудительное взаимодействие добавлен каптон (устранение тяжёлого хвоста) — это изменение модели,
а не критерия.

## Чего quick-валидация не покрывает

* Сходимость по окну для крупных отверстий (600 мкм) и для сапфира на 280 мм — запускать
  `./run.sh simulate sapphire_280mm --hole 20 --window-extra-mm 0.25/1/2` и сравнивать.
* Систематика по плотностям (стеклоуглерод 1.46–1.52, ПММА 1.18/1.19), зазорам, ориентации шаблона,
  подложке — параметры есть в YAML, прогоны не выполнялись.
* Брэгговская дифракция в сапфире и SAXS — вне возможностей Geant4 (docs/physics_model.md §6).
